**Order for cores:** noise study, then engine comparison, then case-b pilot.
Write the option-four redesign while they run.

**Noise study, one engine.** Use the unmodified engine in 2D at Γ 3.5,
f* 0.3 and 0.5, depth 5, with L = 100, 200 and 400. Run eight independent
starts per cell for 3000 cycles, as resumable background jobs over several
nights, within budget. Track the wavelength count over time: start-to-start
differences may anneal slowly or never. By width, report burn-in,
autocorrelation, and start-to-start spread against within-run block spread
for windows of 100 to 2000 cycles. Recommend a pass rule; the referee stays
mine.

**Engine comparison.** Compare the unmodified engine with the nudge condition
by condition, never pooled. Report failure rates by type: overlap, stall or
frozen time, energy residual (positive and negative separately), momentum,
and other. Run whatever cells are empty or thin. Drop plate-stick. Call
positive energy residuals "positive residuals"; the audit's gain counter
counts collisions that gain energy.

**Case b.** Pilot starts where spheres get an upward velocity of ¼, ½ or ¾
of the plate's peak speed, so the first impact compacts the layer gently and
the second landing tests it. Use four seeds each, identical for every engine.
Also try starting from the C code's case-b checkpoint at cycle 2700. Propose
a 3D C baseline for case b.

**Option four: redesign only, no build.**

- Use one resting state, with the plate as a supporter.
- Model it on González's drum example.
- Say what happens when a sphere is held up nonphysically. Compare density
  against depth with and without freezing; overaggressive freezing should
  lock in voids.
- Aim to reduce chatter to something integrable and more physical, not to
  eliminate it.
- Make every cutoff settable, and plan sweeps across external and intrinsic
  parameters.
- Write a validation test plan for each code version.
